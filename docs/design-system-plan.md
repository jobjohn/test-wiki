# 部品の見た目を統一する計画

Storybook（`npm run storybook`）に、画面で使っている部品をすべて登録しました。
この計画は、それを土台にして、部品の見た目と書き方を揃えていく手順です。

## 1. 現状（Storybook 登録時点）

| 区分 | 内容 | 数 |
| --- | --- | --- |
| UI | shadcn/ui の部品（`src/components/ui/`） | 23 部品 |
| Components / Forms / Layout | この Wiki 独自の部品（`src/components/`） | 28 部品（`ActionForm` は見た目を持たないため対象外） |
| Foundations | 配色・文字の一覧 | 2 ページ |
| ストーリー | 状態ごとの表示例 | 126 件 |

- ツールバーで、表示モード 3 種（`light` / `dark` / `system`）を切り替えて確認できます。
- **更新**: カラーテーマ機能は廃止し、配色は shadcn/ui のプリセット `b6rtA2I08` で固定になりました。部品は shadcn/ui をそのまま使い、画面側で見た目を上書きしません。そのため、下の A（文字色の自動選択）は不要になり、B・C・F・G・H も部品の標準の使い方に置き換えて解消しています。
- 登録漏れは、テスト（`tests/stories-coverage.test.ts`）が検出します。新しい部品にストーリーがないと、テストが失敗します。

## 3. 進め方

小さく区切り、各段階の終わりで Storybook の全ストーリーとアプリのテストが通ることを確認します。

### 段階 1: 基準を決める（Foundations）

見た目の「決まり」を先に固定します。

1. **文字色の選択（A）を直す**: 今は明るさの境目（しきい値）で白か黒を選んでいるが、「白と黒のうち、コントラスト比が高いほう」を選ぶ方式に変える。計算では、7 テーマすべてが 4.6:1 以上になる（標準の差し色の緑は、黒文字で 5.38、サンセットの差し色は 6.40）。黒を純黒（`#000000`）にすれば、自由に選んだ色でも 4.6:1 以上になる（`#111827` だと最悪 4.2:1）。`tests/` に「全プリセット・カスタム色で 4.5:1 以上」のテストを足す。
2. **アイコンの大きさ（C）**: 3 種類に絞る。本文・ボタンの中 `size-4`、見出しの横 `size-5`、ページタイトル `size-6`。
3. **余白（E）**: フォームの項目間は `gap-5`、セクション間は `gap-6`、細かい組は `gap-2`。
4. **文字の段階**: Foundations/Typography の 7 種類（ページタイトル・セクション見出し・カード見出し・本文・補足・注記・コード）だけを使う。
5. **画面の幅（D）**: 狭い（フォーム）`max-w-2xl`、標準（設定）`max-w-3xl`、広い（一覧・本文）`max-w-5xl` の 3 種類。

成果物: Foundations に「Spacing」「Icons」「Layout widths」のストーリーを追加。

### 段階 2: 重複を部品にする

書き方が揃うように、繰り返しを共通部品に置き換えます。見た目は変えません。

| 新しい部品・設定 | 解消するバラつき |
| --- | --- |
| `Button` に `variant="destructive-outline"` を追加 | B |
| `SectionTitle`（アイコン + 見出し。大きさは段階 1 の基準） | C・F |
| `PageContainer`（`size="narrow" \| "default" \| "wide"`） | D |
| `FormCard`（`Card` + `ActionForm` + `FormErrors` + 項目間の余白） | E・H |
| `FormActions`（保存・キャンセルの並び。主ボタンは左） | 配置の統一 |
| `TextLink` / `InlineCode` | G |
| `DataCard`（表を載せるカード） | H |

各部品に、使う場面と使ってはいけない場面を `docs` ページ（MDX）で書きます。

### 段階 3: 画面の状態を網羅する

各部品のストーリーに、次の状態を揃えます。

- 通常 / 無効 / エラー / 読み込み中 / 空
- 長い文字（日本語の長い見出し・長い URL）
- ダークモード、スマートフォン幅

操作のあるものは `play` 関数で、実際の操作（入力・クリック・キー操作）まで確認します。

### 段階 4: 自動で守る

決めたことを、人の注意に頼らず機械で守ります。

1. アクセシビリティ（`@storybook/addon-a11y`）を、現在の `todo`（一覧表示のみ）から `error`（失敗にする）へ切り替える。切り替えの前に、違反をすべて解消する。
2. `@storybook/addon-vitest` で、全ストーリーのテストを `npm test` に組み込む。
3. 見た目の変化の検知: 各ストーリーのスクリーンショットを保存し、変更があれば差分を確認する（Playwright で画像比較、または外部サービス）。
4. 色の直書き（`#fff`、`text-red-500` など）を禁止する ESLint ルールを足し、トークン（`text-destructive` など）だけを使わせる。

### 段階 5: 運用ルール

- 新しい部品は、ストーリーと一緒に追加する（テストで強制済み）。
- shadcn/ui の部品を足すときは、`npx shadcn@latest add` で追加し、ストーリーを書き、段階 1 の基準に合うことを確認する。
- 画面のレビューでは、Storybook の公開版（`npm run build-storybook`）を見て、ライト／ダーク・スマートフォン幅の確認を済ませる。

## 4. 優先順位

| 順 | 内容 | 理由 |
| --- | --- | --- |
| 1 | 段階 1-1（文字色の選択） | 読めない組み合わせが、すでに利用者の画面に出ているため |
| 2 | 段階 1 の残り + 段階 2 | 書き方が揃い、以後のバラつきが減る |
| 3 | 段階 3 | 部品ごとの状態を網羅して、確認の漏れをなくす |
| 4 | 段階 4 | 守る仕組みを入れる。違反の解消が済んでから切り替える |

## 5. 完了の基準

- ライト／ダークのどちらでも、文字が 4.5:1 以上で読める。
- 「バラつき」表の A〜H がすべて解消している。
- `src/components/` の全部品にストーリーがあり、全ストーリーが自動テストを通る。
- 新しい画面を作るときに、Storybook の部品だけで組み立てられる。

## 6. 補足

- Storybook ではデータベースとサーバーアクションを使えないため、`.storybook/main.ts` で差し替えています（`src/actions/*` は何もしない、`src/lib/pages.ts` と `src/lib/folders.ts` は固定のサンプルを返す）。そのため、フォームを送信しても保存されません。
- 段階 2 では、データを読む部品（`PageList`・`Markdown`・`FolderBreadcrumbs`）を「見た目だけの部品」と「データを読む部品」に分けると、差し替えが不要になります。
